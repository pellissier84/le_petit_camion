# recherche des manquement de whisperX par rapport annotation elan
# pas de séparation des locuteurs
# travail en cours pour amélioration
Ce que fait ce script :
    1. Extraction des mots métier : Utilise mon ontologie SDIS pour identifier tous les mots/phrases métier dans la référence ELAN (tous locuteurs confondus)
    2. Analyse précise des erreurs :
        ◦ Correct : Le mot métier est présent dans WhisperX
        ◦ Substitution : Le mot a été remplacé par un autre (avec score de similarité)
        ◦ Délétion : Le mot a complètement disparu
        ◦ Insertion : WhisperX a halluciné des mots métier inexistants
    3. Métriques détaillées :
        ◦ WER Métier (taux d'erreur spécifique aux mots métier)
        ◦ Précision par catégorie (CONSCIENCE_NEURO, TRAUMATISME, etc.)
        ◦ Contexte des erreurs pour analyse qualitative
    4. Rapport JSON : Sauvegarde des erreurs détaillées pour analyse ultérieure
Le script ignore complètement la distinction des locuteurs et traite les transcriptions dans leur intégralité.

Ce que ce script apporte  :
1. Double détection des concepts métier :
    • Regex SDIS : Votre ontologie métier spécialisée
    • spaCy NER : Détection automatique des entités (lieux, personnes, dates, etc.)
2. Statistiques par source :
    • Combien de concepts viennent des regex vs spaCy
    • Performance différenciée par type de détection
3. Analyse des insertions enrichie :
    • spaCy valide si les hallucinations sont des entités nommées pertinentes
    • Distingue les vraies hallucinations des erreurs de transcription
4. Rapport détaillé par type :
    • Concepts métier SDIS (votre vocabulaire spécifique)
    • Entités automatiques (lieux, personnes, dates trouvés par l'IA)
Avantages de cette approche :
    1. Complémentarité : Les regex capturent le vocabulaire métier, spaCy capture le contexte général
    2. Robustesse : Si un lieu n'est pas dans votre gazetteer, spaCy peut quand même le détecter
    3. Analyse plus fine : Comprendre quels types d'entités posent problème à Whisper
